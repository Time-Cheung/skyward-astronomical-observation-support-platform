# Skyward 使用与部署手册（中文）

[English](../en/user-and-deployment-guide.md) · [离线安装](../offline-deployment.md)

## 0. 专业人员：最简操作

**先选择 A 仅本机，或 B 受控局域网，二者不要同时占用 8000。** 当前适配 LACT，结果仅是几何候选窗口；无账号、无授权隔离，不可公网发布。只有服务器安装 Python 依赖、访问可选 IERS/Gaia 外部服务；客户端只需浏览器及到服务器的网络。

以下所有路径、用户名、组、IP、CIDR、网卡和服务名均为**示例，必须按部署机器替换**，不是当前服务器信息。示例项目 `/opt/skyward`，部署用户/组 `skyward`，Python `/opt/python-3.9.21/bin/python3`，服务器内网 IP `192.168.50.10`，批准客户端网段 `192.168.50.0/24`，端口 `8000`。勿直接复制不属于自己网络的 IP/CIDR。

Python **3.9.21 是已验证版本**，以下路径与 Conda 命令用于复现该环境，不是唯一可部署补丁版本。其他兼容 Python 版本必须保留固定依赖并重新运行完整测试，不能据此假定任何新版本都兼容。

先取得代码，以下二选一；`REPOSITORY_URL` 替换为维护者确认的真实仓库地址，父目录由管理员授权部署用户写入。已有生产副本应在维护窗口按第 8 节处理，优先独立候选目录；先备份本地修改，不自动 stash、reset、清理或覆盖。

```bash
# 首次获取：目标目录尚不存在
git clone REPOSITORY_URL /opt/skyward
```

```bash
# 已有副本：检查后仅允许干净副本快进
cd /opt/skyward
git status --short
if [ -z "$(git status --porcelain)" ]; then git pull --ff-only; else echo 'STOP: preserve local changes first'; fi
```

有未保存修改、远程分叉或拉取失败就停止，备份并人工处理；仅成功后继续。离线服务器以受控版本包替代联网 clone/pull。

```bash
# 共同准备：在服务器、以项目及运行目录的所有者执行
cd /opt/skyward
/opt/python-3.9.21/bin/python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python -c 'import sys,numpy,astropy; print(sys.version); assert numpy.__version__=="1.26.4"; assert astropy.__version__=="6.0.1"; print(sys.executable, numpy.__version__, astropy.__version__)'
mkdir -p .runtime/matplotlib .runtime/cache
export MPLCONFIGDIR="$PWD/.runtime/matplotlib" SKYWARD_CACHE_DIR="$PWD/.runtime/cache"
# 完整测试，不只跑 smoke 子集；保留输出及退出码
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -p no:cacheprovider -q
```

- **A 本机**：`.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`；在**服务器本机**访问 `http://127.0.0.1:8000/`，健康地址为其 `/api/v1/health`。
- **B 局域网**：先完成第 4 节防火墙限制，再运行 `.venv/bin/python -m uvicorn app.main:app --host 192.168.50.10 --port 8000`；在服务器及授权客户端访问 `http://192.168.50.10:8000/`（替换为服务器真实内网 IP）。仅在防火墙已经限制可信网段时才可改为 `--host 0.0.0.0`。
- 常驻服务分别参考 `deploy/skyward-local.service` 和 `deploy/skyward-lan.service`。先手工验证、停止前台进程，再按下文安装。本文是操作说明，**本次文档修改未安装、启动、停止或替换现有服务，也未修改防火墙**。

## 1. 新手教程：认识服务器和安全边界

“服务器”是运行 Skyward Python 程序的 Linux 主机；“客户端”是打开网页的电脑。客户端不必安装 Python、Conda、NumPy 或源表，也不需要直连 Gaia/IERS。只有服务器的可选在线功能需要经过批准的出站访问；纯离线几何计算使用本地数据。

`127.0.0.1` 永远指访问命令所在的机器。客户端上的 `127.0.0.1` 不是服务器。`0.0.0.0` 是所有 IPv4 接口的监听地址，**不是浏览器访问地址**。绑定内网 IP 也不等于限制客户端身份，仍需防火墙。不要公网端口映射、反向代理到公网、设置全网允许规则或在排错时关闭防火墙。

当前 LACT 站点为东经 `100.0266666667°`、北纬 `29.3575°`、海拔 `4410 m`，理想圆形 FoV 直径 `8.3°`，实时遥测未接入时固定天顶参考。天气、云、气溶胶、设备状态、机械限位、跟踪误差、真实响应/灵敏度和联合观测条件不在几何判断内。不能把几何绿色或候选窗口视为正式批准。

## 2. 共同准备（A/B 都必须完成）

1. 按第 0 节首次 clone 或已有副本快进流程取得可信项目版本（离线用受控版本包），由管理员提供 Linux 主机、Python（已验证 **3.9.21**，其他兼容版本需重测）和必要的目录权限。项目可放其他位置，但全文与 unit 中的路径必须同步替换。不要用 root 运行网页服务。
2. 确认部署用户/组存在，能遍历项目父目录、读取代码和 `data/`，手工启动时能写 `.runtime/`；systemd 使用单独的 `/var/cache/skyward-local` 或 `/var/cache/skyward-lan`。无需使整个项目对所有人可写。
3. 在服务器终端进入项目，执行第 0 节**全部共同准备命令**。`.venv` 是默认且唯一的项目运行环境；不要使用 `sudo pip` 或裸 `pip/uvicorn` 混入服务器全局 NumPy 2.x。`requirements.txt` 保持原固定依赖，包括 **NumPy 1.26.4、Astropy 6.0.1**。
4. 检查数据包（包括源表、来源元数据和 `data/iers/finals2000A.all`）完整，计划日期在活动 IERS 表覆盖内；安装包不能只有代码。无外网服务器先按[离线说明](../offline-deployment.md)准备 wheelhouse。
5. 完整 pytest 返回非零时停止发布，保留日志排查。本文提供验证命令和验收清单，**不代表本轮全部功能已经通过最终发布验收**。

### 可选 Conda 替代（不要混用）

只有管理员决定采用 Conda 时，才以独立环境替代 `.venv`：

```bash
conda create -n skyward python=3.9.21 pip
conda activate skyward
python -m pip install -r requirements.txt
python -m pip check
python -c 'import sys,numpy,astropy; print(sys.version); assert numpy.__version__=="1.26.4"; assert astropy.__version__=="6.0.1"; print(sys.executable)'
```

后续所有 `.venv/bin/python` 均替换成该环境的 **Python 绝对路径**，如 `/opt/miniforge/envs/skyward/bin/python`（示例需替换），unit 的 `ExecStart` 也相应调整。systemd 不依赖 shell 的 `conda activate`。不要同时向两个环境装包。

## 3. 部署 A：仅服务器本机访问

### A1. 手工启动与检查

完成共同准备后，在服务器终端运行：

```bash
cd /opt/skyward
export MPLCONFIGDIR="$PWD/.runtime/matplotlib" SKYWARD_CACHE_DIR="$PWD/.runtime/cache"
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

保持此终端，在服务器第二个终端运行：

```bash
ss -ltnp | grep ':8000'
curl -fsS http://127.0.0.1:8000/api/v1/health
curl -fsS http://127.0.0.1:8000/api/v1/config
```

服务器本机浏览器打开 `http://127.0.0.1:8000/`。无桌面服务器可先用 curl；不要为了查看网页擅自改成全网监听。预期只看到 `127.0.0.1:8000`，不应出现 `0.0.0.0:8000`、`[::]:8000` 或内网监听。**A 不需要对局域网开放 8000 防火墙端口。**

### A2. 可选 systemd 常驻

以下 `skyward-local.service` 是示例服务名；先核对机器现有服务，避免误替换。审阅模板，替换 `User`、`Group`、`WorkingDirectory`、`ExecStart` 和缓存路径。示例用户/组为 `skyward`，项目为 `/opt/skyward`。

停止刚才的前台进程（Ctrl+C）后，由有权限的管理员执行：

```bash
cd /opt/skyward
sudo install -d -o skyward -g skyward -m 0750 /var/cache/skyward-local
sudo install -d -o skyward -g skyward -m 0750 /var/cache/skyward-local/matplotlib /var/cache/skyward-local/data
sudo -u skyward test -w /var/cache/skyward-local/matplotlib
sudo -u skyward test -w /var/cache/skyward-local/data
sudo install -m 0644 deploy/skyward-local.service /etc/systemd/system/skyward-local.service
sudo systemctl daemon-reload
sudo systemctl enable --now skyward-local.service
systemctl status skyward-local.service --no-pager
journalctl -u skyward-local.service -n 100 --no-pager
ss -ltnp | grep ':8000'
curl -fsS http://127.0.0.1:8000/api/v1/health
```

`MPLCONFIGDIR` 和 `SKYWARD_CACHE_DIR` 都在该服务允许写入的缓存根目录内；IERS 使用后者下的 `iers/`。模板不依赖全局可写 `/tmp` 或可写 home。旧 `lact-window-planner.service` 模板也改为本机监听；需要 LAN 时应显式选 LAN 模板，不能假设旧服务已被更改。

### A3. 排错与验收

- 本机 curl 失败：检查进程/上述服务状态、日志、端口冲突及 `.venv` 绝对路径；确认在服务器而不是客户端执行。
- 无监听：先查启动错误、依赖、数据和缓存权限；不要以开放防火墙解决应用未启动。
- 本机通、远端不通：这是 A 的正确隔离结果；VLAN 路由或放行规则不应被调整来绕过它。
- 验收：本机页面/API 可用、监听仅回环；远端以服务器内网 IP 访问 8000 应失败；确认无其他代理/转发对外暴露。按第 6 节检查健康 JSON，并按第 7 节做功能验收。

## 4. 部署 B：受控局域网访问

### B1. 确认真实地址与防火墙

完成共同准备后，在**服务器**执行：

```bash
ip -4 -brief address
ip route
ss -ltnp | grep ':8000'
```

由网络管理员确认客户端可路由的内网地址、网卡、批准源 CIDR 和 VLAN/访问控制列表（ACL），不是随便取第一个 Docker/VPN/回环地址。下面继续用 `192.168.50.10` 与 `192.168.50.0/24` 作例子，二者**必须替换**。

先审阅现有策略。仅加一条可信网段 accept 规则**不能撤销已有的全网允许规则**。需要默认拒绝其他来源，并确认 IPv6、上游 ACL、NAT 和所有相关接口没有旁路。禁止 `--add-port=8000/tcp` 式不加来源限制的放行，不要关闭防火墙。

下面是 **firewalld 专用**的规则片段，仅供管理员审核后使用，不是通用初始化脚本；`internal` 是示例 zone，必须替换为实际承载内网接口且不默认放行所有流量的 zone：

```bash
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --zone=internal --list-all
# 先确认此 zone 的默认策略拒绝未批准访问，清理冲突宽泛规则需另行审核
sudo firewall-cmd --permanent --zone=internal \
  --add-rich-rule='rule family="ipv4" source address="192.168.50.0/24" port protocol="tcp" port="8000" accept'
sudo firewall-cmd --reload
sudo firewall-cmd --zone=internal --list-all
```

若采用 nftables、UFW 或上游设备，请让管理员配置等效的“只准受信源 CIDR、拒绝其余来源”策略，不要叠加未知的防火墙管理器。最终以批准与未批准网络的实际访问测试为准。

### B2. 手工启动与客户端访问

```bash
cd /opt/skyward
export MPLCONFIGDIR="$PWD/.runtime/matplotlib" SKYWARD_CACHE_DIR="$PWD/.runtime/cache"
.venv/bin/python -m uvicorn app.main:app --host 192.168.50.10 --port 8000
```

优先绑定服务器**具体真实内网 IP**。只有已验证防火墙限制可信网段时，才可把 host 改为 `0.0.0.0`；这会监听所有 IPv4 接口，但不改变浏览器 URL。

服务器第二终端及授权客户端分别执行：

```bash
curl -fsS http://192.168.50.10:8000/api/v1/health
curl -fsS http://192.168.50.10:8000/api/v1/config
```

客户端浏览器访问 `http://192.168.50.10:8000/`，其中 IP 是服务器真实内网地址；**不能使用 `0.0.0.0` 或客户端的 `127.0.0.1`**。绑定具体内网 IP 时，服务器 `curl http://127.0.0.1:8000` 失败不表示故障，应查绑定地址。

### B3. 可选 systemd 常驻

`skyward-lan.service` 是本节示例真实操作名；不要误用 A 的 `skyward-local.service`。模板的 `192.168.50.10` 必须在安装前改为服务器真实内网 IP，同时替换用户、组、项目和缓存路径。确认前述防火墙已生效，Ctrl+C 停止本节手工进程，再执行：

```bash
cd /opt/skyward
sudo install -d -o skyward -g skyward -m 0750 /var/cache/skyward-lan
sudo install -d -o skyward -g skyward -m 0750 /var/cache/skyward-lan/matplotlib /var/cache/skyward-lan/data
sudo -u skyward test -w /var/cache/skyward-lan/matplotlib
sudo -u skyward test -w /var/cache/skyward-lan/data
sudo install -m 0644 deploy/skyward-lan.service /etc/systemd/system/skyward-lan.service
sudo systemctl daemon-reload
sudo systemctl enable --now skyward-lan.service
systemctl status skyward-lan.service --no-pager
journalctl -u skyward-lan.service -n 100 --no-pager
ss -ltnp | grep ':8000'
curl -fsS http://192.168.50.10:8000/api/v1/health
```

### B4. 排错与验收

- 服务器访问绑定 IP 失败：先查服务、日志、`ss`、实际 IP 是否存在、缓存权限及端口冲突。`Cannot assign requested address` 通常是模板 IP 未替换或接口未就绪。
- 服务器通、客户端不通：检查客户端 URL、防火墙来源 CIDR、接口所属 zone、路由、VLAN 间 ACL 和上游隔离；“同为内网”不等于同 VLAN 或可互通。ping 成功不代表 TCP 8000 已放行。
- A 的回环监听遗留：核对当前进程与 unit 的 `ExecStart`；不要同时启动 A/B 抢占同一端口。
- 验收：服务器和授权客户端可访问真实内网 IP；未批准网段不可访问；无公网映射；监听与选择一致。若使用 `0.0.0.0`，还要验证其他接口上的未批准访问被拒绝。
- 按第 6 节读健康 JSON，按第 7 节核验网页/API；记录测试网络、时间、版本和结果，不要只以 HTTP 200 判定部署通过。

## 5. 界面、科学语义与已实现功能

显示语言（中文/English）、主题（自动/亮/暗）、时区（默认北京 UTC+8，可选 UTC）保存在浏览器 `localStorage`。坐标显示可切换地平、J2000、银道；显示变换不改变内部几何语义。自动主题跟随系统。升级后先硬刷新（Ctrl+Shift+R），仍有旧设置问题时再备份本地计划并按需清除本站 localStorage。

这些是当前接入的数据规模，不是已部署、已推送或已完成全量验收的声明；当前仍待最终发布审查。TeVCat 截止日期不代表以后实时同步；采集依据见[采集说明](../tevcat-acquisition.md)。上传 CSV 是临时源表，不应静默覆盖发布数据。

TeVCat 的 `unverified_excerpts` 是待核验短摘录，不能当作测量值。当前 361 条均为 `footprint_known=false`、`planning_radius_deg=null`；`is_extended=false` 也不能证明可用的硬边界。与 2LHAASO 的关联中 **verified=0、候选186**，只表示候选关系，不能把位置邻近或 1LHAASO 关系当成同一天体，也不向 2LHAASO 复制 TeVCat 参数。

源详情备注应展示单位（units）、来源（provenance）、数据版本/引用、核验状态以及缺失值；未知 footprint/extension 必须明确标为未知，不能用绘图点或默认 `0` 冒充已测物理半径，不能据此声称“完整源”已包含在 FoV 内。跨表近邻不自动等同于同一天体。

Gaia DR3 只提供**候选定标星**，不是已认证的定标标准。当前实现由浏览器在基础天图就绪后，独立请求 **`GET /api/v1/gaia`** 并异步等待该 HTTP 响应；**不是服务端 job 创建/轮询接口**。等待是前端请求状态，接口本身不返回 job ID。

| 参数/返回字段 | 含义 |
|---|---|
| `target_source_key` | 已选源的稳定标识；未指定目标时按当前指向查询，不能把一次查询的行号当长期身份 |
| `map_kind` | `current` 或 `local-fov`；局部图需目标标识或完整目标坐标 |
| `radius_deg`、`limit`、`max_mag` | 按需锥形范围及亮度/数量限制；默认 `5°`、`500`、`18`，允许范围分别 `0.1–15°`、`1–2000`、`5–22` |
| `sources`、`overlay_svg`、`gaia` | 成功响应含源记录、叠加 SVG 和状态元数据；状态也展平在顶层 |
| `count` / `drawn_count` | 返回记录数 / 当前投影实际画出的标记数；不要求二者相等 |
| `cached`、`error`、`zero` | 缓存命中、查询错误、成功零行；`zero=true` 不是错误 |
| `limit`、`truncated` | 请求数量上限及是否有超出上限的结果；截断不等于完整天空清单 |
| `selection`、`ordering`、`brightest_n` | `bounded_unordered_subset`、`unspecified`、`false`：有界无序子集，不是最亮 N 颗，也不是代表性抽样 |
| `query_timeout_seconds` | 当前独立 Gaia 网络查询配置为 **20 秒**有限超时，不是页面或整条 HTTP 请求在所有环境下的严格总耗时保证 |

默认仍为半径 **5°**、最多 **500** 行、**G≤18**。为避免密集锥形区域的全量排序，查询不使用 `ORDER BY`；不能按返回顺序推断亮度排名，也不能用这个子集推断完备性或总体统计。并发查询上限 **2**、响应上限 **2 MiB**、进程缓存上限 **32** 个查询。超时或并发限制是错误，不是成功零行；缩小范围或稍后重试，不影响基础地图独立加载。

查询失败仍可能返回 HTTP 200，顶层 `status="error"`、`error` 非空、`zero=false`；错误响应可能没有 `gaia`、`overlay_svg` 或 `drawn_count`，客户端需容错。成功零行通常 `status="zero"`、`error=null`。只有 HTTP 成功不能证明 Gaia 科学查询成功；不能把失败当零星源。Gaia `source_id` 是字符串；当前仅将 J2016.0 方向做 ICRS→FK5 J2000 坐标系转换，**未做自行传播**。缓存是有界进程内缓存，不承诺重启持久保存。断网时本地源表及基础几何不依赖此层，新 Gaia 查询不能保证可用。完整参数以 `/openapi.json` 为准。

**1000× 缩放只放大显示，不增加天文数据、角分辨率、定位精度或物理模型分辨率。** 小角尺度下仍须显示原始误差与来源，不能把屏幕像素当测量精度。

### 状态与规划操作

- GREEN：已知中心及名义 extension 满足相应几何条件；YELLOW：中心通过但已知边缘不能完全满足；RED：中心不通过。未知 footprint 的源不能套用“完整已验证”解释。
- 当前天空状态使用当前指向/FoV；候选跟踪窗口不能被误读为实时设备指向批准。`ext_err` 和位置误差不自动等同 extension 或参与颜色阈值。
- 选择源表及源，或填写新目标 RA、Dec、半径；名称可为空，自动生成 `TMP JHHMM±DDMM`。临时目标不写入原始 2LHAASO。
- 选择起止时刻（单次最多 1 天），网页无 offset 输入按所选时区解释；API 使用带 `Z` 或显式 offset 的 ISO 8601。
- 默认约束：太阳高度不高于 `-18°`，月距至少 `30°`，目标天顶角 `0°–60°`，最短窗口 `0 s`；页面要求填写全部五项，API 的可空性以 OpenAPI 为准。
- 候选逐秒扫描，已发现的通过/失败边界进一步细化；最短时长设为零不等于保证发现所有亚秒窗口。
- 观测计划只接受包含至少两个经复核有效整秒的完整源窗口，端点向内部取整；计划保存在浏览器，不是服务器正式排班。下载文件为 **`skyward-observing-plan.zip`**，其中必含 `skyward-observing-plan.txt`；添加计划时勾选保存图表才附带对应 SVG，可只下载含 TXT 的 ZIP。

## 6. 健康检查、IERS 与接口

常用接口：`/api/v1`（参考页）、`/openapi.json`、`GET /api/v1/health`、`GET /api/v1/config`、`GET /api/v1/catalogues`、`GET /api/v1/sources`、`GET /api/v1/sky/current`、`GET /api/v1/gaia`、`POST /api/v1/catalogues/upload`、`POST /api/v1/windows/calculate`。交互式 Swagger/ReDoc 默认禁用，静态资源不依赖外部 CDN。

健康检查需读 JSON，不能只看 curl 的 HTTP 成功：

- `status` 依据 IERS 是否覆盖当前时刻为 `ok` 或 `degraded`；不代表所有源表、Gaia、科学结果均通过。
- `iers.source_kind="bundled"`：当前活动表来自内置/回退文件。
- `iers.source_kind="online_cache"`：当前活动表来自在线缓存，**可能是以前的下载，不证明本次联网成功**。查看 `last_attempt`、`last_success`、`last_error`；这些是当前进程状态，重启后可能为空。
- 同时查看 `source`、`cache_path`、`first_mjd/last_mjd`、`covers_current_time`、`current_values_are_predicted`、`age_seconds`、`update_due` 和 `update_interval_days`。

依据 `app/astronomy.py`：启动时新鲜缓存优先，否则载入 bundled 回退，随后启动后台有界联网刷新；成功才解析并原子替换缓存/活动表，失败保留活动表并记录错误。配置中 7 天用于缓存新鲜度/到期信息，**不是独立定时器，也不能承诺长运行进程每周自动刷新**。Astropy 隐式 `auto_download=False`，但应用自己的启动刷新仍会尝试外联；严格隔离环境由出站策略控制，不能因为此字段为 false 就推断没有外联。当前请求超时配置为 6 秒，不应把它宣称为所有网络情况下的总耗时硬上限。

IERS-A 未来部分可能为预测值。当前时刻健康不代表任意未来规划日期被覆盖；超出活动表覆盖的计算请求可返回 HTTP 422。排查 422 还应检查起止顺序、单次 1 天限制和角度参数。

## 8. 升级、回滚与维护

下面以 A 的 **`skyward-local.service` 为示例实际操作名**；部署 B 时，把所有服务命令替换为你实际安装的 **`skyward-lan.service`**。如果实际仍使用旧 `lact-window-planner.service`，就使用该名，不能照抄不存在的 `skyward.service`。本节命令仅供运维执行，本次未运行。

升级前记录现行提交、活动 unit（含 drop-in）、数据/元数据哈希、环境版本、缓存来源与可恢复备份。在维护窗口内确认工作区无未保存修改，记录可信的旧版本标记 `PREVIOUS_GOOD_REF`（占位符需替换）：

```bash

git status --short
git rev-parse HEAD
systemctl cat skyward-local.service
.venv/bin/python -m pip freeze
# 上述工作区非干净时停止；备份必须包含代码、数据、环境与 unit
# 仅快进，不自动合并或覆盖本地修改
git pull --ff-only

.venv/bin/python -c 'import sys,numpy,astropy; print(sys.version); assert numpy.__version__=="1.26.4"; assert astropy.__version__=="6.0.1"; print(sys.executable)'

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -p no:cacheprovider -q
```
