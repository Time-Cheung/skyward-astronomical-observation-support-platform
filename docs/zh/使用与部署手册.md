# Skyward 使用与部署手册（中文）

## 1. 概述

Skyward 是 LACT 的局域网几何观测窗口规划工具。它读取 190 个 `2LHAASO` 源，在 LHAASO/LACT 站点位置计算太阳、月亮和目标的地平坐标，并给出观测候选窗口。

**本版本只做几何判断。** 它不评估天气、云、气溶胶、LACT 实时状态、当前机械指向、机械限位、跟踪误差、真实离轴响应、实际灵敏度或 LHAASO 联合观测条件。页面和 API 中的结果不能作为正式观测批准。

## 2. 用户界面

### 2.1 显示设置

主页面顶部右侧提供三个本地设置：

- **语言**：中文和 English；
- **时区**：默认 **北京: UTC+8**，也可切换为 **UTC**；
- **主题**：自动、亮色和暗色。

主题、语言和时区保存在该浏览器的 `localStorage` 中。计算或结果页刷新需要服务端重新生成 SVG 图表时，会随该次请求传递当前主题和时区，但**不会在服务端持久化**，也不需要账号。自动主题会跟随操作系统配色。时区切换会统一影响首页日期输入、全天图的日期时钟、窗口页面时间、观测计划编辑器，以及新一次计算生成的曲线图横轴。Skyward 的基础视觉色为黑、白和品牌蓝 `#3333FF`；绿色、黄色、红色只用于源状态语义。

### 2.2 全天图

全天图使用本地地平坐标投影：

- 图心是天顶方向和 LACT 站点标记，当前版本的实时 FoV 圆固定指向天顶，等待实时指向遥测接入；
- 外圈为地平线，标签显示在圆盘西北侧外部以避免与方位标记重叠；
- 可见源以星形显示；地平线下源不画入圆盘；
- 太阳和月亮采用小型橙色 `☀︎`、`☾` 图标；
- 面板实时显示当前日期时钟、太阳和月亮的高度/方位；可选择实时每分钟刷新或指定日期时间；
- 点击任意源星标可打开源详情，详情标题右侧的“填入观测规划”可直接选择该源。

状态定义：

| 颜色 | 含义 |
|---|---|
| 绿色 GREEN | 源中心和名义 extension 均满足地平线、已启用约束和 8.3°硬 FoV。 |
| 黄色 YELLOW | 源中心通过，但 extension 边缘不能完整满足 FoV、地平线、天顶角或月距条件。 |
| 红色 RED | 源中心不满足地平线、太阳或已启用的中心约束。 |

`ext_err` 和 `p_err(95%)` 仅供显示，不参与颜色计算。

### 2.3 规划窗口

1. 在“目标源”中选择一个 `2LHAASO` 源，或保留默认的“添加新目标”；
2. 选择“添加新目标”时，填写 RA、Dec、半径。目标名称可留空，系统将按坐标生成 `TMP JHHMM±DDMM`；
3. 设定开始和结束时间。页面的无时区输入按右上角选定的“北京: UTC+8”或“UTC”解释。因为规划器会逐秒扫描，单次计算范围最多为 **1 天**；
4. 所有五项约束均需填写，不能留空。默认值为太阳最大高度 `-18°`、月亮最小角距 `30°`、目标天顶角 `0°-60°`、最短窗口 `0 s`；
5. 点击“计算窗口”。

可选参数：

| 参数 | 规则 |
|---|---|
| 太阳最大高度角 | `Sun altitude <= 输入值`；范围为 `-90°` 至 `-15°`，默认 `-18°`。 |
| 月亮最小角距 | 目标中心到月心角距 `>= 输入值`，默认 `30°`。 |
| 目标最小天顶角 | 限制目标不要过近天顶，默认 `0°`。 |
| 目标最大天顶角 | 限制目标不要过近地平线，默认 `60°`。 |
| 最短连续窗口 | 仅保留连续满足条件且持续时间不少于该秒数的窗口，默认 `0 s`。 |

候选网格会在整个请求时段内按 **1 秒间隔**计算。相邻秒点出现通过/失败变化时，再把对应的约束边界二分细化到亚秒。因此，`minimum_window_seconds=0` 的含义是“不额外按持续时间筛除”，**不会**恢复到旧版的一分钟采样。只要一个有效时段至少包含一个采样秒点，就会被保留。若数学上的有效时段短于 1 秒，且它位于已发现的相邻秒点交叉之间，结果仍可能显示细化后的边界；但在没有更高分辨率的物理事件求解器前，不能承诺发现所有短于 1 秒的时段。

可下载的观测计划采用更严格的语义：只有完整源窗口中至少存在两个经过几何复核的有效整秒时，才显示“加入观测计划”。预填的开始和结束时间均向窗口内部取整并再次独立验证，避免浏览器只支持秒精度的 `datetime-local` 控件把计划落到细化边界的无效一侧。

## 4. Conda 部署流程（推荐）

Conda 环境能与服务器全局 Python、ROOT 或其他科学软件隔离。以下命令以 Miniforge/Mambaforge 为例；若使用 Anaconda，请将 `mamba` 改为 `conda`。

### 4.1 安装或确认 Conda

先确认命令可用：

```bash
conda --version
# 或
mamba --version
```

如需安装 Miniforge，请由服务器管理员在可信网络或离线介质上获取适合 Linux x86_64 的安装包。安装后重新登录 shell，或执行：

```bash
source ~/miniforge3/etc/profile.d/conda.sh
```

### 4.2 创建独立环境

```bash
cd /home/lact/wz/lact-window-planner
source ~/miniforge3/etc/profile.d/conda.sh
mamba create -y -n skyward python=3.9 pip
# 若没有 mamba：conda create -y -n skyward python=3.9 pip
conda activate skyward
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

验证版本：

```bash
python --version
python - <<'PY'
import astropy, fastapi, numpy
print("astropy", astropy.__version__)
print("fastapi", fastapi.__version__)
print("numpy", numpy.__version__)
PY
```

项目固定使用 `astropy==6.0.1` 与 `numpy==1.26.4`。不要把系统 Python 或安装有 NumPy 2.x 的全局环境混入此环境。

### 4.3 离线安装

在可联网且 Python/系统架构兼容的维护机上准备 wheel：

```bash
mkdir -p skyward-wheelhouse
python -m pip download -r requirements.txt -d skyward-wheelhouse
```

将 `skyward-wheelhouse/` 和项目目录通过受控介质复制到内网服务器，然后：

```bash
conda activate skyward
python -m pip install --no-index --find-links ./skyward-wheelhouse -r requirements.txt
```

不要在隔离服务器运行时打开 Astropy IERS 自动下载。Skyward 使用 `data/iers/finals2000A.all`。

## 5. 测试与手工启动

进入 Conda 环境后：

```bash
cd /home/lact/wz/lact-window-planner
conda activate skyward
MPLCONFIGDIR=/tmp/skyward-mpl PYTHONDONTWRITEBYTECODE=1 \
  python -m pytest -p no:cacheprovider -q
```

本机启动：

```bash
MPLCONFIGDIR=/tmp/skyward-matplotlib \
  uvicorn app.main:app --host 127.0.0.1 --port 8000
```

局域网启动前，必须确认防火墙网段：

```bash
MPLCONFIGDIR=/tmp/skyward-matplotlib \
  uvicorn app.main:app --host 0.0.0.0 --port 8000
```

当前服务器地址如仍为 `10.2.101.152`，访问：

```text
http://10.2.101.152:8000/
```

健康检查：

```bash
curl -fsS http://127.0.0.1:8000/api/v1/health
```

## 6. systemd 以 Conda 环境运行

`deploy/lact-window-planner.service` 默认使用项目 `.venv`。若改用 Conda，复制为独立 unit 并将 `ExecStart` 改为 Conda 环境中的 uvicorn 绝对路径，例如：

```ini
[Service]
User=lact
Group=lact
WorkingDirectory=/home/lact/wz/lact-window-planner
Environment=MPLCONFIGDIR=/var/cache/skyward/matplotlib
ExecStart=/home/lact/miniforge3/envs/skyward/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=read-only
ReadWritePaths=/var/cache/skyward
```

> `ExecStart` 必须按实际安装位置修改。用 `which uvicorn` 和 `conda env list` 确认。

安装：

```bash
sudo install -d -o lact -g lact /var/cache/skyward/matplotlib
sudo install -m 0644 deploy/lact-window-planner.service /etc/systemd/system/skyward.service
# 编辑 /etc/systemd/system/skyward.service，将 ExecStart 改为 Conda 路径
sudo systemctl daemon-reload
sudo systemctl enable --now skyward.service
sudo systemctl status skyward.service
journalctl -u skyward.service -f
```

## 7. 网络安全边界

Skyward 没有账号和权限系统。能连接端口的客户端都可访问页面和 API。必须通过主机防火墙或上游网络设备，仅允许可信局域网 CIDR，不能做公网映射。

示例（执行前由网络管理员确认网段）：

```bash
sudo firewall-cmd --permanent \
  --add-rich-rule='rule family="ipv4" source address="10.2.0.0/16" port protocol="tcp" port="8000" accept'
sudo firewall-cmd --reload
```

检查监听端口：

```bash
ss -ltnp | grep ':8000'
```

## 8. API 与时间

- API 参考页：`/api/v1`
- OpenAPI schema：`/openapi.json`
- 健康检查：`/api/v1/health`
- 窗口计算：`POST /api/v1/windows/calculate`

API 时间建议使用 UTC 的 ISO 8601 格式，如 `2026-12-15T10:00:00Z`。网页日期时间按右上角时区设置解释，默认是北京时间；选择 UTC 后，网页的日期和时间输入、全天图、窗口表和后续曲线图均使用 UTC。

计算时间必须被 `data/iers/finals2000A.all` 覆盖；超出表格范围时，详情、全天图和窗口 API 会返回 HTTP 422。IERS-A 表中未来段是预测值，应定期更新。

## 9. 更新数据

### 9.1 更新 IERS

在可信联网维护环境下载官方 `finals2000A.all`，以受控介质替换：

```text
data/iers/finals2000A.all
```

验证：

```bash
conda activate skyward
python - <<'PY'
from astropy.time import Time
from astropy.utils import iers
path = "data/iers/finals2000A.all"
table = iers.IERS_A.open(path)
print("rows:", len(table))
print("first MJD:", table["MJD"][0].value)
print("last MJD:", table["MJD"][-1].value)
print("last UTC:", Time(table["MJD"][-1].value, format="mjd").iso)
PY
python -m pytest -q
```

随后重启服务：

```bash
sudo systemctl restart skyward.service
```

### 9.2 更新源表与补充信息

替换源表前必须保留字段语义和 190 行结构。启动时会校验表头、连续 index、唯一名称、RA/Dec 范围和数值有限性。任何 TeVCat 或其他补充字段应先人工核验，再写入 `data/source_enrichment.json`；缺失信息保持 `null` 或空列表，不能按名称猜测。

## 10. 故障排查

| 现象 | 检查方法 |
|---|---|
| 页面无法打开 | `systemctl status skyward.service`、`journalctl -u skyward.service -n 100`、`ss -ltnp \| grep ':8000'`。 |
| API 健康状态 degraded | 检查 `data/iers/finals2000A.all` 是否存在、是否覆盖当前日期。 |
| 计算返回 422 | 检查时间顺序、最多 1 天限制、角度范围、最小天顶角不大于最大天顶角，以及 IERS 覆盖范围。 |
| 图表字体或 Matplotlib 错误 | 确认 `MPLCONFIGDIR` 指向可写目录。 |
| 启动时 NumPy/Astropy 报错 | 确认已 `conda activate skyward`，并重新执行 `python -m pip install -r requirements.txt`。 |
| 浏览器语言或主题没有变化 | 清除该站点 localStorage 后刷新；设置仅保存在当前浏览器。 |

## 11. 维护检查表

- 定期检查 IERS 文件末日期；
- 每次依赖或数据更新后运行 pytest；
- 定期核验防火墙仍只开放批准网段；
- 保持 `source_enrichment.json` 的来源和核验状态可追溯；
- 后续接入天气、遥测或账号前，重新进行安全与科学验收。
