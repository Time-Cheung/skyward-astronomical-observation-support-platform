# Skyward User and Deployment Guide (English)

## 1. Overview

Skyward is a LAN-only geometry planner for LACT observing. It loads the 190-source `2LHAASO` catalogue, computes horizon coordinates for targets, the Sun and the Moon at the LHAASO/LACT site, and reports candidate observing windows.

**This release is geometry only.** It does not evaluate weather, clouds, aerosols, live LACT telemetry, current mechanical pointing, mechanical limits, tracking error, off-axis response, real sensitivity, or LHAASO joint-observation acceptance. A result is not a formal observing approval.

## 2. Using the web interface

### 2.1 Display settings

The upper-right controls on the main page provide:

- **Language**: Chinese or English;
- **Time zone**: **Beijing: UTC+8** by default, or **UTC**;
- **Theme**: Auto, Light or Dark.

The browser stores these choices in `localStorage`. When a calculation or result refresh needs a server-rendered SVG plot, the current theme and time-zone choice travel with that one request; they are **never persisted server-side** and do not require accounts. Auto follows the operating-system colour scheme. Changing time zone updates planner inputs, the all-sky clock, result timestamps, the observing-plan editor, and the x-axis of plots generated by the next calculation. Skyward uses black, white and brand blue `#3333FF` as its visual foundation. Green, yellow and red are reserved for observing-status meaning.

### 2.2 All-sky map

The all-sky map is a local horizon-coordinate projection:

- the centre is zenith and the LACT site marker; the current-version real-time FoV circle is fixed at zenith until pointing telemetry is connected;
- the outer ring is the horizon, with its label placed outside the north-west side to avoid compass overlap;
- visible sources are stars; below-horizon sources are omitted from the disc;
- the Sun and Moon use small orange `☀︎` and `☾` symbols;
- a live panel shows the current clock and Sun/Moon altitude and azimuth, with live one-minute refresh or a selected time;
- click a source star to open details. The top-right **Use for planning** action fills that source into the planner.

Status semantics:

| Colour | Meaning |
|---|---|
| Green | The centre and nominal extension pass the horizon, enabled constraints and the 8.3° hard FoV. |
| Yellow | The centre passes, but an extension edge fails the FoV, horizon, zenith-angle or Moon-separation requirement. |
| Red | The centre fails the horizon, solar or enabled centre constraint. |

`ext_err` and `p_err(95%)` are displayed but do not change the colour.

### 2.3 Planning a window

1. Select a `2LHAASO` source, or keep the default **Add new target** option;
2. With **Add new target**, enter RA, Dec and radius. The name may be blank, in which case Skyward derives `TMP JHHMM±DDMM` from the coordinates;
3. Choose start and end times. A timezone-free web `datetime-local` input is interpreted in the selected header time zone, Beijing: UTC+8 or UTC. A single calculation can cover at most **one day** because the planner scans every requested second;
4. Fill all five constraints. They are required. Defaults are Sun maximum altitude `-18°`, Moon minimum separation `30°`, target zenith range `0°-60°`, and minimum window `0 s`;
5. Select **Calculate windows**.

Optional inputs:

| Input | Rule |
|---|---|
| Maximum Sun altitude | `Sun altitude <= value`; range `-90°` through `-15°`, default `-18°`. |
| Minimum Moon separation | Target-centre to Moon-centre separation `>= value`, default `30°`. |
| Minimum target zenith angle | Prevents a target from being too close to zenith, default `0°`. |
| Maximum target zenith angle | Prevents a target from being too close to the horizon, default `60°`. |
| Minimum continuous window | Keeps only continuous intervals at least this many seconds long, default `0 s`. |

The candidate grid is evaluated at one-second cadence over the requested interval. Pass/fail transitions found at adjacent seconds are then bisected to a sub-second boundary. Therefore `minimum_window_seconds=0` means “do not apply an additional duration filter”; it does **not** restore the former one-minute sampling. A valid excursion that contains at least one sampled second is retained. A mathematically valid interval shorter than one second can still be shown after boundary refinement when it is bounded by sampled transitions, but it cannot be guaranteed to be discovered without a higher-resolution physical/event solver.

For a downloadable observing plan, Skyward deliberately uses stricter semantics: it offers the action only when the full-footprint interval contains at least two geometry-checked whole-second instants. Its prefilled start and end are rounded inward and independently re-evaluated, so the browser’s second-precision `datetime-local` controls cannot shift a plan onto the invalid side of a refined boundary.

## 4. Conda deployment, step by step

Conda isolates Skyward from the system Python, ROOT and other scientific software. The commands below use Miniforge/Mambaforge. Replace `mamba` with `conda` if needed.

### 4.1 Install or verify Conda

```bash
conda --version
# or
mamba --version
```

If Miniforge is required, obtain the correct Linux x86_64 installer through an approved network or offline transfer. After installation, initialise the shell:

```bash
source ~/miniforge3/etc/profile.d/conda.sh
```

### 4.2 Create the environment

```bash
cd /home/lact/wz/lact-window-planner
source ~/miniforge3/etc/profile.d/conda.sh
mamba create -y -n skyward python=3.9 pip
# If mamba is unavailable: conda create -y -n skyward python=3.9 pip
conda activate skyward
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Verify versions:

```bash
python --version
python - <<'PY'
import astropy, fastapi, numpy
print("astropy", astropy.__version__)
print("fastapi", fastapi.__version__)
print("numpy", numpy.__version__)
PY
```

The project pins `astropy==6.0.1` and `numpy==1.26.4`. Do not mix the system interpreter or a global NumPy 2.x installation into this environment.

### 4.3 Offline package installation

On an approved networked maintenance machine with a compatible Python and operating system, download wheels:

```bash
mkdir -p skyward-wheelhouse
python -m pip download -r requirements.txt -d skyward-wheelhouse
```

Transfer `skyward-wheelhouse/` and the project through controlled media. On the isolated server:

```bash
conda activate skyward
python -m pip install --no-index --find-links ./skyward-wheelhouse -r requirements.txt
```

Do not enable Astropy IERS auto-download on the isolated server. Skyward reads `data/iers/finals2000A.all`.

## 5. Test and start manually

Run the suite:

```bash
cd /home/lact/wz/lact-window-planner
conda activate skyward
MPLCONFIGDIR=/tmp/skyward-mpl PYTHONDONTWRITEBYTECODE=1 \
  python -m pytest -p no:cacheprovider -q
```

Local-only start:

```bash
MPLCONFIGDIR=/tmp/skyward-matplotlib \
  uvicorn app.main:app --host 127.0.0.1 --port 8000
```

LAN start, only after confirming the firewall policy:

```bash
MPLCONFIGDIR=/tmp/skyward-matplotlib \
  uvicorn app.main:app --host 0.0.0.0 --port 8000
```

If the server address is still `10.2.101.152`, open:

```text
http://10.2.101.152:8000/
```

Health check:

```bash
curl -fsS http://127.0.0.1:8000/api/v1/health
```

## 6. Running systemd with Conda

The supplied `deploy/lact-window-planner.service` uses the project `.venv` by default. If Conda is preferred, copy the unit and change `ExecStart` to the absolute path of the Conda executable, for example:

```ini
[Service]
User=lact
Group=lact
WorkingDirectory=/home/lact/wz/lact-window-planner
Environment=MPLCONFIGDIR=/var/cache/skyward/matplotlib
ExecStart=/home/lact/miniforge3/envs/skyward/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=read-only
ReadWritePaths=/var/cache/skyward
```

> Adjust `ExecStart` to the real installation path. Use `which uvicorn` and `conda env list` to confirm it.

Install and enable:

```bash
sudo install -d -o lact -g lact /var/cache/skyward/matplotlib
sudo install -m 0644 deploy/lact-window-planner.service /etc/systemd/system/skyward.service
# Edit /etc/systemd/system/skyward.service and change ExecStart to the Conda path
sudo systemctl daemon-reload
sudo systemctl enable --now skyward.service
sudo systemctl status skyward.service
journalctl -u skyward.service -f
```

## 7. Network security boundary

Skyward has no accounts or permission system. Any client that can reach the port can use all pages and APIs. Restrict the port to the approved LAN CIDR using the host firewall or an upstream network device. Do not publish or port-forward it to the Internet.

Example, to be reviewed by the network administrator first:

```bash
sudo firewall-cmd --permanent \
  --add-rich-rule='rule family="ipv4" source address="10.2.0.0/16" port protocol="tcp" port="8000" accept'
sudo firewall-cmd --reload
```

Check listeners:

```bash
ss -ltnp | grep ':8000'
```

## 8. API and time handling

- API reference: `/api/v1`
- OpenAPI schema: `/openapi.json`
- Health: `/api/v1/health`
- Window calculation: `POST /api/v1/windows/calculate`

Use explicit UTC ISO 8601 timestamps for API calls, for example `2026-12-15T10:00:00Z`. Browser datetimes are interpreted using the header time-zone setting, Beijing: UTC+8 by default or UTC when selected. In UTC mode, planner inputs, the all-sky view, result timestamps and plots calculated afterward use UTC.

Requested times must be covered by `data/iers/finals2000A.all`. Detail, sky and window APIs return HTTP 422 outside the table range. The future portion of IERS-A is predictive and should be refreshed periodically.

## 9. Updating data

### 9.1 Update IERS

Download the official `finals2000A.all` in an approved maintenance environment and replace:

```text
data/iers/finals2000A.all
```

Validate it:

```bash
conda activate skyward
python - <<'PY'
from astropy.time import Time
from astropy.utils import iers
path = "data/iers/finals2000A.all"
table = iers.IERS_A.open(path)
print("rows:", len(table))
print("first MJD:", table["MJD"][0].value)
print("last MJD:", table["MJD"][-1].value)
print("last UTC:", Time(table["MJD"][-1].value, format="mjd").iso)
PY
python -m pytest -q
```

Restart the service:

```bash
sudo systemctl restart skyward.service
```

### 9.2 Update the catalogue and enrichment

Before replacing the catalogue, preserve its field meanings and 190-row structure. Startup validation checks the header, contiguous indices, unique names, RA/Dec ranges and finite numeric values. TeVCat or other enrichment must be manually verified before entering `data/source_enrichment.json`; missing information stays `null` or an empty list and must not be guessed from similar names.

## 10. Troubleshooting

| Symptom | Check |
|---|---|
| Page cannot be opened | `systemctl status skyward.service`, `journalctl -u skyward.service -n 100`, and `ss -ltnp \| grep ':8000'`. |
| Health is degraded | Check that `data/iers/finals2000A.all` exists and covers the current date. |
| Calculation returns 422 | Check time order, the maximum **one-day** range, angle ranges, minimum zenith ≤ maximum zenith, and IERS coverage. |
| Matplotlib font or cache error | Set `MPLCONFIGDIR` to a writable directory. |
| NumPy/Astropy startup error | Confirm `conda activate skyward`, then run `python -m pip install -r requirements.txt`. |
| Language or theme does not change | Clear this site's localStorage and reload. The setting belongs to the current browser. |

## 11. Maintenance checklist

- Check the final date of the IERS file periodically;
- Run pytest after every dependency or data update;
- Periodically verify that the firewall still exposes only the approved LAN;
- Keep enrichment provenance and verification status traceable;
- Repeat security and scientific acceptance before adding weather, telemetry or accounts.
