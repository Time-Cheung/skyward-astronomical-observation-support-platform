What Skyward is

V2.2 (full version 2.2.20260924) reports explainable geometric-feasibility candidates only. It does not determine operational readiness or approve an observation.

AVAILABLE NOW

Current functions

Browse supported catalogues, inspect all-sky and local-field geometry, view source details, and calculate centre and full-footprint windows under explicit geometric constraints.

PRODUCT GOAL

Decision support

Provide read-only, reproducible and explainable evidence that helps an operator or scientist prepare an observing decision.

FUTURE DEVELOPMENT

Evidence not yet connected

After authoritative inputs and validation are available, future versions may add live pointing and device telemetry, weather and atmosphere, mechanical trajectory limits, instrument availability, and joint-observation evidence.

How to use Skyward

  1. Open the sky map.Return to “Sky map & planner” and open the catalogue selector inside the sky-map area.
  2. Select catalogue layers and confirm.The page loads the checked catalogues and draws their markers only after you confirm the selection.
  3. Choose a target and conditions.Select a source, set the time range and geometric constraints, then calculate the windows.
  4. Interpret the result within scope.Green, yellow and red describe geometry only. Check weather, device state, mechanics and operating approval separately.

Returning to a result

When you leave a calculated result for Data notes or API, this browser tab keeps the rendered result view. Returning through Sky map & planner restores it without recalculating the windows or reloading either map. A direct refresh or unavailable browser storage uses the normal server rebuild.

Observing plans

The full-footprint section has one shared set of plan actions. Each valid window is listed on its own row with a checkbox selected by default. Add to the plan creates one target entry containing all checked windows; the preview edits each planned interval separately, while the XLSX records one target row per selected window and keeps alternatives attached to the corresponding window. A user-uploaded CSV can be selected as the exclusive alternative-source directory for that plan; without it, the selected ordinary catalogues remain the candidate pool.

The downloaded workbook uses a solid black header, yellow target rows, and green alternative rows. It is generated locally in the browser; no plan is uploaded to the server. Saved observing-window SVGs include comparison-curve legends; saved local-FoV SVGs use a light background, assign the target ID 1, and include a source-name legend.

CSV upload formats and examples

Both uploads use UTF-8 CSV with a header row. Column names are case-insensitive; coordinates are degrees in J2000. Save example files as UTF-8 CSV.

The source-catalogue filename becomes its display label. Upload an alternative-source directory using the dedicated control in the full-footprint section of a result page.

User-uploaded source catalogue

Required columns: name, ra, dec. Optional columns: ext, ext_err, p_err(95%), l, b. You may also use source_name, ra_deg, dec_deg, or extension_deg as aliases. Missing optional values can be left blank; ext defaults to 0. One unique name per row is required.

Download source-catalogue CSV example

name,ra,dec,ext,ext_err,p_err(95%)
Crab,83.6331,22.0145,0.10,0.02,0.01
Example source,120.5,-30.2,,,

Dedicated alternative-source catalogue

Use the same CSV format. Required columns: name, ra, dec; optional columns are the same as above. Upload it in the alternative-source controls on a result page. It is used exclusively to search alternatives for that plan and does not replace the selected target or displayed catalogues.

Download alternative-catalogue CSV example

name,ra,dec,ext
Alternative A,84.0,22.3,0.15
Alternative B,75.25,12.8,0

Limits: up to 1,000 rows and 512 KiB per file. Names must be unique (case-insensitive) and 1–80 characters; coordinates must be finite, with 0 ≤ RA < 360 and −90 ≤ Dec ≤ 90. Negative extension or uncertainty values are rejected. The reserved unpublished 2LHAASO name cannot be used.

Column-name aliases: source_name for name, ra_deg for ra, dec_deg for dec, and extension_deg for ext.

Source status

GREEN — The source centre and nominal extension both pass the active geometric constraints.

YELLOW — The centre passes, but the full source footprint does not.

RED — The source centre fails the active geometric constraints.

Selected target — Blue hollow star outline marks the source chosen for calculation.

Tracked-FoV source — Purple hollow star outline marks a source inside the tracked FoV during an observation-window calculation.

Gaia DR3 calibration star — A thicker red/green cross is an on-demand Gaia candidate whose geometry is unavailable/observable in the shared map mode; calibration suitability is not assessed.

True extension — Cyan dashed circle marks the nominal source footprint when a verified radius is available.
